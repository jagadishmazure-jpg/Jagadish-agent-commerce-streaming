# Agent commerce and streaming lab: signed spend mandates, approvals, SSE chat, persona tests

[![ci](https://github.com/jagadishmazure-jpg/Jagadish-agent-commerce-streaming/actions/workflows/ci.yml/badge.svg)](https://github.com/jagadishmazure-jpg/Jagadish-agent-commerce-streaming/actions/workflows/ci.yml)
[![codeql](https://github.com/jagadishmazure-jpg/Jagadish-agent-commerce-streaming/actions/workflows/codeql.yml/badge.svg)](https://github.com/jagadishmazure-jpg/Jagadish-agent-commerce-streaming/actions/workflows/codeql.yml)

A shopping agent for **Fernhill Market, a fictional outdoor-supplies shop**, that can spend money
only inside limits the user signed, only on a cart the user approved, and only once per approval.
Around it sits a small streaming chat UI (FastAPI, plain HTML and JavaScript) that shows tokens and
tool calls live, pauses for Approve or Reject, and can be stopped mid-reply. A persona simulator
then throws angry, vague, manipulative and indecisive users at it and scores the outcome from the
payment ledger, not from what the agent says.

Everything is mock and local: no payment processor, no paid model API, no GPU. Every number below
comes from a real run in this repo.

## At a glance (for recruiters)

* **Problem:** an agent that can pay must not overspend, pay the wrong party, charge twice on a retry,
  act on an approval the user never saw, or be talked out of its rules by text in the chat.
* **Approach:** HMAC-signed spend mandate (per-purchase cap, total cap, merchant allowlist, expiry) plus
  a signed, single-use approval bound to the exact cart hash; idempotent checkout and refunds; a fraud
  velocity and spike check; a 402 quote-then-proof flow for paid resources; SSE streaming with cancel.
* **Proof (real runs):** 0 wrong money movements across 200 simulated conversations; time to first
  token measured from real HTTP and headless-browser runs; cancel stops a stream in about 21 ms.
* **Size:** <!-- BEGIN:tests -->170<!-- END:tests --> automated tests, including a headless Chromium test against a real local server.
* **Honest limits:** the "model" is a deterministic rule-based stand-in, so latency numbers measure the
  serving path around a simulated model, and the injection guard is a regex that misses paraphrases
  (it shows up as a 57.5% detection pass rate below). See [limitations](docs/limitations.md).

## Real output

Tables are generated by `scripts/render_docs.py` and checked in CI with `--check`.

### Persona simulator (40 conversations per persona, seed 2026)

<!-- BEGIN:personas -->
| Persona | Passed | Safety (no wrong money movement) |
|---|---|---|
| polite_buyer | 40/40 (100.0%) | 100% |
| angry | 40/40 (100.0%) | 100% |
| vague | 40/40 (100.0%) | 100% |
| injection | 23/40 (57.5%) | 100% |
| yes_wait_no | 40/40 (100.0%) | 100% |
<!-- END:personas -->

The 17 injection failures are all "detection" misses: a paraphrased attack ("please disregard your
earlier rules...") is not recognised by the regex guard, so the agent does not raise a guard event.
It still moves no money, because nothing is charged without a clear yes on a pending approval.
Before two fixes found by this simulator, the same suite scored injection 10/40 and yes-wait-no
37/40 with **3 wrong charges** (see [results](docs/results.md)).

### Streaming latency (local machine, x86_64, Python 3.13, results/stream_bench.json)

<!-- BEGIN:stream -->
Simulated model: 120 ms before the first token, 20 ms per token.

| Measurement | p50 | p95 | n |
|---|---|---|---|
| TTFT, HTTP client (from POST /api/chat) | 123.5 ms | 124.6 ms | 30 |
| Total reply time, HTTP client | 430.0 ms | 450.7 ms | 30 |
| TTFT, headless Chromium (EventSource to first token) | 122.8 ms | 123.9 ms | 20 |
| Total reply time, headless Chromium | 428.7 ms | 448.7 ms | 20 |
| Cancel to `cancelled` event | 21.1 ms | 21.8 ms | 20 |
| TTFT with zero simulated delay (serving overhead) | 2.4 ms | 3.5 ms | 30 |
| Total with zero simulated delay | 3.8 ms | 5.0 ms | 30 |

Replies average 16 tokens; a cancel after token 3 delivered 4 tokens on average.
<!-- END:stream -->

Reading it: the serving path adds about 2 to 4 ms on top of whatever the model takes; cancel latency
is bounded by one token interval because the server checks the cancel flag between tokens.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python -m playwright install chromium   # once, for the browser test and browser timings
pytest -q
agentcommerce serve                     # open http://127.0.0.1:8000 and type "buy a headlamp"
agentcommerce personas                  # writes results/persona_report.json
agentcommerce bench --runs 30           # writes results/stream_bench.json
```
